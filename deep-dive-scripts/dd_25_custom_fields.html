1
What Custom Fields Are and Why They Matter

Custom Fields let you extend the data model in Rev.io PSA to capture information specific to your business. Every company has information that doesn't fit neatly into standard PSA fields — a security system code for a customer site, a lease expiration date on an asset, a job reference number required by a specific customer, or a technician's certification level relevant to a ticket type. Custom fields let you add those fields directly inside PSA rather than maintaining a parallel spreadsheet or relying on technicians to put special information in notes.

Custom fields are available on: Tickets, Customer accounts, Assets, Purchase Orders, and Recurring Services. Each object has its own set of custom fields configured independently.

→ Connects ToCustom Fields connect to: Tickets (fields appear on the ticket creation and edit screens), Customers (fields appear on the customer profile), Assets (fields appear on asset detail and edit screens), Purchase Orders (additional tracking fields on POs), Recurring Services (service-specific metadata), Workflows (custom field values can be used as workflow conditions), and Analytics (custom field data is available in custom reports).
▲ Platform ImpactWithout custom fields, teams work around missing data with inconsistent note formats, external spreadsheets, or whiteboard solutions. Custom fields bring that information inside PSA — where it's searchable, reportable, and part of the official record.

3
Building Custom Fields — Step by Step

Navigate to Admin > Custom Fields Manager. You'll see the Custom Field Builder tab. Select the object you want to add fields to (Tickets, Customers, Assets, etc.), then click Add Field.

Field Configuration

SettingDescription
Field NameThe label that appears next to the field in the UI. Use clear, descriptive language your team will understand.
Field TypeThe data type — see the table above
RequiredWhether the field must be filled before saving the record
Default ValueA pre-populated value (optional). Useful for fields that are almost always the same.
OptionsFor Dropdown and Multi-Select fields: the list of choices available
Min / Max SelectionsFor Multi-Select fields: how many options the user can select
ActiveWhether the field currently appears in the UI

Field Layout — Controlling Where Fields Appear

The Layouts tab in the Custom Fields Manager lets you control where custom fields appear within the record — their order, which section they show in, and for tickets specifically, whether a field appears on all ticket types or only on specific ones.

💡 Pro TipFor tickets, use layouts to show different fields for different ticket types. A 'Break/Fix' ticket might need an 'Equipment Failure Description' field. An 'Installation' ticket might need a 'Site Readiness Confirmed' checkbox. Configuring layouts per ticket type keeps each ticket form clean and relevant.
4
Custom Fields on Each Object

Ticket Custom Fields

Appear on the ticket creation and edit screens under an 'Additional Information' section. Visible to techs in the web app and mobile app. Can be used as conditions in workflow rules. Searchable and filterable in the ticket list view.

Customer Custom Fields

Appear on the customer profile screen. Useful for account-level information that applies across all tickets for that customer — customer tier, site access instructions, account manager name, preferred contact method.

Asset Custom Fields

Appear on the asset detail and edit screens. Useful for equipment-specific data — software version, firmware version, warranty number, physical location within a building, managed status in a third-party system. Viewable and editable in the mobile app.

Purchase Order Custom Fields

Appear on PO records. Useful for internal tracking fields like approval reference number, department code, or project allocation.

Recurring Service Custom Fields

Appear on recurring service records. Useful for service-specific metadata like circuit ID, service agreement reference number, or monitored device count.

5
Using Custom Fields in Reports

Custom field data is available in the Analytics module when building custom reports. Select the object (Tickets, Customers, Assets) as your data source, and your custom fields will appear as available columns alongside standard fields.

This is what makes custom fields truly powerful — not just capturing the data, but being able to report on it. A dropdown field for 'Customer Tier' lets you filter your revenue report by tier. A date field for 'Warranty Expiry' lets you build a report of all assets expiring in the next 90 days.

💡 Pro TipBefore building custom fields, think about whether you'll want to report on the data. Text Area fields are great for notes but difficult to aggregate in reports. Dropdowns and Checkboxes are far more reportable. When in doubt, use a Dropdown instead of a Text field.

Action Items

  • Identify all information currently tracked outside PSA that should be inside it
  • Map each piece of information to an object (Ticket, Customer, Asset, PO, Service) and field type
  • Build custom fields for each identified need
  • Configure layouts so fields appear in logical order and only where relevant
  • Mark required fields for any information that must always be captured
  • Test each field by creating a test record and confirming the field behaves as expected
  • Include key custom fields in your default Analytics report columns
