1
What Bulk Tools Are

Bulk Tools is an Admin-only section that provides utilities for large-scale data operations — importing, updating, and managing records in volume rather than one at a time. It's most valuable during initial setup (importing an existing product catalog or historical payment records) and for ongoing maintenance (bulk-updating catalog pricing after a rate change).

Each bulk tool includes role-based access control — only admins with the appropriate permission can access Bulk Tools. All bulk operations are logged in the Audit Log for traceability.

⚠ Watch OutBulk operations apply changes to many records simultaneously and cannot be undone with a single action. Always use a test file with a small number of records before running a full bulk import or update. Validate results on 5–10 records before committing to the full dataset.
2
Product Import

Product Import lets you add new products to the catalog in bulk by uploading a CSV or Excel file, rather than creating each product one at a time.

When to Use It

  • Migrating from another PSA or field service system — your existing product catalog can be exported as CSV and imported here
  • Adding a large batch of new products from a distributor catalog
  • Initial setup when you have more than 20–30 products to add

Process

  • Navigate to Admin > Bulk Tools > Product Import
  • Download the CSV template — this defines the required and optional columns
  • Populate the template with your product data
  • Upload the file — drag-and-drop supported
  • Review inline validation errors and correct them
  • On the Review step: if there are errors, download the Failed Records CSV, fix those rows, and re-upload — you don't have to start over
  • Confirm and import
💡 Pro TipStart with your Labor rate items and your top 20–30 most-used parts and services. Get those right first, validate them in the system, then run a second import for the remainder of the catalog. This catches template and mapping issues before they affect your full dataset.
3
Product Update

Product Update lets you make bulk changes to existing catalog items — price updates, cost updates, category changes, or any other product field — without editing each item individually.

When to Use It

  • Annual price increase across multiple items
  • Cost update after receiving new distributor pricing
  • Category restructuring affecting many items
  • Activating or deactivating a batch of items

Process

  • Navigate to Admin > Bulk Tools > Product Update
  • Download your current product catalog as a file
  • Open the file and modify only the fields you want to change — all other data is preserved
  • Upload the modified file
  • Review and confirm
⚠ Watch OutOnly modify the fields you intend to change. If you accidentally change a price or clear a field on the downloaded file, that change will be applied. Review the file carefully before uploading.
4
Payment Import

Payment Import allows historical payment records from a legacy system to be imported into PSA during migration. This is a one-time operation during go-live — it ensures the billing history in PSA reflects payments received before PSA was implemented.

The import validates each payment record against the customer's bill profile before applying it. Upload a CSV or Excel file with payment details matching the required template.

❓ PromptAre you migrating from another system that has historical payment records you want in PSA? This is something to plan for before go-live — ideally with a clean cutover date so it's clear what belongs in the import vs. what will be entered going forward.
💡 Internal NotePayment Import is primarily a migration tool. Ongoing payments should be recorded through the normal billing workflow or collected automatically through autopay. Don't use Payment Import for regular operations.
5
Audit Logs

The Audit Log in Admin > Audit Logs records all system activity and user actions across PSA. You can filter by user, action type, date range, and module. Each log entry shows who did what, when, and on which record.

The Audit Log is your forensic record for: investigating a record that was accidentally changed or deleted, understanding why a billing discrepancy occurred, verifying that a workflow fired as expected, or demonstrating compliance with data governance requirements.

💡 Pro TipMake a habit of checking the Audit Log when investigating any unexpected data change. 'Someone changed that price' or 'that ticket was closed but we didn't do it' — the Audit Log will tell you exactly who and when.

Action Items

  • Use Product Import if you have more than 30 catalog items to set up — don't do it manually
  • Run a test import with 5–10 records before the full dataset
  • Download the Failed Records CSV when errors occur rather than starting over
  • Plan Payment Import if migrating from a system with historical payment history
  • Establish who has access to Bulk Tools — keep it to billing admins and system admins
  • Check the Audit Log when investigating any unexpected data changes
