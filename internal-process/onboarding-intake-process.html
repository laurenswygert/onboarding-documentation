Sales-Sourced Deals SALES

The full intake workflow for a new deal closed by Sales, start to finish.

  1. Sales closes the deal, which auto-generates the Onboarding Sales Brief. Onboarding Leadership then reviews that brief for completeness, reviews the contract, and confirms everything is notated as it should be.
    • If there are any gaps — missing addendums, contract terms, or other information — the brief is pushed back to the Sales Rep for correction before moving forward.
  2. Onboarding Leadership preps the project: generates a complexity score, uses automation to create the project channels and templates, creates the client instance, and assigns an Onboarding Consultant (OC) and, as needed, a Data Engineer (DE) — within three business days of everything being handed back to Onboarding Leadership.
  3. The project status changes to "Ready for Onboarding," and a message is posted in the project channel tagging the project team, with links to the sales brief and the complexity calculator.
  4. Sales sends an email introduction to the client.
  5. The Onboarding Consultant proposes call times within 24 hours of the intro email being sent, and gets the kickoff call set on the calendar within 48 hours of that email. The call itself doesn't have to occur within 48 hours — it just needs to be on the calendar by then.

Requirements & Things to Know

  • Data load approach: Sales is required to provide API credentials. If they're available, the standard 60-calendar-day timeline applies; if not, the client uses the Data Migration Template and the timeline extends by two weeks to 75 calendar days.
  • 2-week data load gate: if the data load information hasn't been received from the client within two weeks of Onboarding Leadership's brief review, the project is returned to Sales until it's provided — nothing moves forward without the data load, regardless of progress on any other part of the project.

Existing Client Migrations MIGRATION

This follows a workflow closely mirroring the Sales process, for existing clients migrating from Tiger Paw or adding on the new UI for legacy billing.

What Qualifies

  • Qualifies: the account is migrating from Tiger Paw, or an existing legacy billing client is adding on the new Rev.io UI — this always requires a full onboarding project.
  • Does not qualify: routine account-management support questions that don't involve a platform migration or UI add-on.

The full intake workflow, start to finish:

  1. Account Management manually completes the Onboarding Brief (in lieu of the auto-generated version Sales produces for new deals) and submits it to the Intake Channel. Onboarding Leadership then reviews that brief for completeness, reviews the contract, and confirms everything is notated as it should be.
    • If there are any gaps — missing addendums, contract terms, or other information — the brief is pushed back to Account Management for correction before moving forward.
    • Part of the Onboarding Brief discloses whether this is a Tiger Paw migration or a new-UI add-on for a legacy billing client, and the brief's questions adjust accordingly to collect the specific technical information needed for that path.
  2. Onboarding Leadership preps the project: generates a complexity score, uses automation to create the project channels and templates, creates the client instance, and assigns an Onboarding Consultant (OC) and, as needed, a Data Engineer (DE) — within three business days of everything being handed back to Onboarding Leadership.
  3. The project status changes to "Ready for Onboarding," and a message is posted in the project channel tagging the project team, with links to the onboarding brief and the complexity calculator.
  4. An email introduction is sent to the client — TBD whether this is owned by Sales or Account Management on a migration.
  5. The Onboarding Consultant proposes call times within 24 hours of the intro email being sent, and gets the kickoff call set on the calendar within 48 hours of that email. The call itself doesn't have to occur within 48 hours — it just needs to be on the calendar by then.

Requirements & Things to Know

  • Data load approach: API credentials are required. If they're available, the standard 60-calendar-day timeline applies; if not, the client uses the Data Migration Template and the timeline extends by two weeks to 75 calendar days.
  • 2-week data load gate: if the data load information hasn't been received within two weeks of Onboarding Leadership's brief review, the project is returned to Account Management until it's provided — nothing moves forward without the data load, regardless of progress on any other part of the project.

Return to Onboarding RETURN

This looks similar to what's outlined for Existing Client Migrations, but needs more structure.

What Qualifies

  • Qualifies: there's a genuine, documented gap in the client's original training — they were never adequately trained on core functionality — and they need full retraining.
  • Does not qualify: a one-off support question, a minor how-to request, or a refresher that Client Success can handle directly without a full onboarding re-engagement.
Open item: confirm this qualifying criteria with Onboarding Leadership and Client Success — drafted here based on the distinction discussed, but not yet official policy.

The full workflow, start to finish — several steps below are marked TBD because the level of detail provided doesn't yet confirm whether the full Sales/Migrations sequence applies to a returning account or a lighter-weight version is used, flagged for confirmation with Onboarding Leadership and Client Success:

  1. Client Success provides a detailed outline of why the account is being returned and what specific training needs to occur — this path is for accounts with genuine gaps in their initial training, not just a request for extra support. If the return is data-load-related, CS includes specific documentation of the issue and what's needed to resolve it. Onboarding Leadership reviews this documentation for completeness. TBD — the exact scope of this review hasn't been confirmed, but is expected to be lighter-weight than a new deal or conversion since there's no new contract involved.
    • If there are gaps in the outline, training plan, or data load documentation, it's pushed back to Client Success for correction.
  2. Onboarding Leadership preps the project: handles complexity scoring and instance check as applicable, and assigns (or reassigns) an Onboarding Consultant (OC) and, as needed, a Data Engineer (DE) — within three business days of everything being handed back to Onboarding Leadership. TBD — since a returning account's instance already exists, whether a new complexity score is generated or the instance step is skipped/abbreviated hasn't been confirmed.
  3. The project status changes to "Ready for Onboarding," and a message is posted in the project channel with a link to the return documentation.
  4. The Onboarding Consultant reaches out to the client to schedule time to begin the returned work or training — no intro email is needed since the relationship already exists. TBD — whether the same 24-hour-proposal / 48-hour-scheduling SLA used for new-client kickoffs applies here hasn't been confirmed.

Requirements & Things to Know

  • Data load issues (if applicable): TBD — Onboarding determines what's needed to resolve a data-load-related return, but whether this follows the same API-credentials-vs.-Data-Migration-Template decision and 60/75-day timeline used on new deals hasn't been confirmed.

Requires a detailed written reason for the return and the specific training needed. If data load issues triggered the return, specific documentation of the issue and what's needed must be included.
