1
Why User Management Comes First

We always start with User Management because every other part of the platform depends on it. The users you create here are the people who will own tickets, log time, get dispatched to jobs, process billing, and run reports. The permissions you assign determine what each of those people can see and do. The groups you create will be referenced directly in System Settings when we configure ticket routing — so getting this right first means everything downstream will work the way you expect.

→ Connects ToUser groups flow directly into System Settings ticket defaults, the Dispatch Board for scheduling, and ticket assignment throughout the platform. Permission sets control access to Billing, Quoting, Customers, Admin, and every other module.
▲ Platform ImpactIf users don't have the right permissions, they'll either be blocked from doing their job or have access to sensitive financial data they shouldn't see. If user groups aren't set up before System Settings, you won't be able to configure your default ticket routing.
2
Creating a User
❓ PromptBefore we dive in — let's make sure everyone on the call can actually get into the system. Go ahead and navigate to [clientname].psarev.io and log in now. Let me know once you're in and we'll walk through this together.

Go to Admin > User Management > Add User. Let's walk through the key fields together:

  • Email — this is also their login username. The system sends a password reset link here, so it must be their actual work email.
  • Role — a high-level label like Technician, Dispatcher, or Admin. Think of it as a job title in the system, not a security setting.
  • Permission Set — this is the security setting. It controls exactly what the user can access and do. We'll build these next.
  • User Group — how the system knows which team this person belongs to for ticket routing and scheduling.
  • Active toggle — must be on. Deactivating a user immediately removes their access.
❓ PromptLet's create your first user now. Who should we start with?

One thing to pass along to your team: the password reset email that gets sent to new users expires after 12 hours. Make sure new users know to check their inbox right away and set their password before that window closes. If someone misses it, an admin can resend the link directly from the User Management list — no big deal, just an extra step.

3
Permission Sets

Permission sets answer one question: what is each type of user allowed to see and do in Rev.io PSA? Every module — Ticketing, Billing, Quoting, Admin, Inventory — has its own set of permissions you can toggle on or off. The best practice is to build one permission set per role type on your team, then assign users to the set that matches their job.

To give you a head start, we've prebuilt three permission sets in your instance that cover the most common role types:

  • Admin — Has access to everything in the system. Intended for your team members who need full visibility and control.
  • Standard User — Has access to most areas needed for day-to-day operations. A good fit for dispatchers, office staff, and anyone who isn't a technician but isn't a full admin either.
  • Field Technician — Limited primarily to ticketing and mobile app functionality. Keeps things simple for techs in the field who only need what's relevant to their work orders.

You can use these as-is or customize them to fit your team. We'll loop back to permissions once we've walked through all the modules — at that point you'll have a much better sense of exactly what each role should and shouldn't see, and we'll confirm everything is dialed in correctly.

Go to Roles & Permissions > Add Role. Name it by role — 'Technician,' 'Dispatcher,' 'Admin.' Then toggle on the access that role needs. You can always come back and adjust these as you learn what your team needs.

❓ PromptWhat roles do you have on your team? Let's build a permission set for your most common role right now.
▲ Platform ImpactPermission sets are how you protect sensitive data. A technician probably shouldn't see billing or be able to delete customer records. An admin needs full access. Getting these right early prevents support headaches later.
→ Connects ToPermissions apply across every module — Billing, Quoting, Customers, Admin settings, Inventory, and Reports. If a user can't see something they need, the first place to check is their permission set.
💡 Internal Note — Permissions InterfaceThe permissions list displays as a vertical list with expandable categories. Use the search bar to find a specific permission without expanding everything, or use Expand All / Collapse All when doing a full review. This is good to know before the call so you can navigate confidently — no need to walk the client through the UI mechanics.
💡 Internal Note — Role CopyingA Copy option is available in the menu next to each existing role. Use this to build upward — copy Technician to create Senior Technician, then add the extra permissions. Suggest this approach to clients who are building multiple similar roles. The Pro Tip: build the most restrictive role first, then copy up to more permissive ones. Faster and less error-prone than starting from scratch each time.

Notable Permission Categories to Walk Through

As you're building out permission sets together, make sure to cover these categories — they come up frequently and clients are often surprised by the granularity available:

  • Time Management: Controls who can edit and delete time entries and time clock entries. Includes a separate permission for viewing hourly rates — useful for keeping wage data private from junior staff.
  • Project Management: Controls who can create, view, edit, and delete projects. Note that Global Administrators are the only users who can access Projects by default — all other users need this permission explicitly granted.
  • Opportunities: Controls who can create, view, edit, and delete opportunity records.
  • Inventory Management: Controls who can adjust costs and quantities, enable/disable inventory, create or delete reservations, transfer inventory, and view the inventory matrix.
  • Custom Fields: Controls who can manage custom fields for assets, customers, purchase orders, and tickets.
💡 Internal Note — User Creation WorkflowUsers can now be assigned to user groups and roles during the initial creation process — no need to create the user first and go back to edit them. Keep this in mind as you walk the client through adding their team.
💡 Internal Note — Email Setting Location ChangeThe "Assign Ticket on Email Domain Match" setting has moved from Service in System Settings to the Email category under Inbound Email Options. Updating it in either location syncs across all mailboxes automatically. Flag this if a client mentions they can't find it where they expect.
4
User Groups
❓ PromptHow is your team structured — do you have separate groups for different work types, skill sets, or regions?

User groups are how Rev.io PSA knows which team a ticket or scheduled job should go to. When a ticket comes in — whether from email, the customer portal, or created manually — the system needs to know who should see it. That's controlled by the Default Ticket User Group setting, which we'll set in System Settings in a few minutes. It references the groups you build here.

Go to User Groups > Add User Group, name it, and add users. A user can belong to multiple groups — someone can be on both the general support team and an escalation team at the same time.

→ Connects ToUser groups feed directly into System Settings (default ticket routing), the Dispatch Board (filter by team), and ticket assignment (assign to a group vs. an individual). They also show up in reporting so you can measure performance by team.

Action Items

  • Add all team members as users
  • Build one permission set per role type
  • Create at least one user group before moving to System Settings
  • Remind new users to set their password within 12 hours
